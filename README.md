## 왜 만들었나요?

생산·재고 관리에서는 가격이 올랐다는 정보만으로 다음 행동을 결정하기 어렵습니다. **현재 원료가 며칠 버티는지, 입고까지 얼마나 걸리는지, 생산계획을 맞추려면 언제 몇 톤을 주문해야 하는지**를 함께 봐야 합니다.

이 프로젝트는 공공데이터를 수집·분석하는 데서 시작해, 재고·입고 예정·생산계획·배합표 CSV를 연결하고 **원료 부족 → 제품별 계획 영향 → 대응안 비교 → 조치 기록**까지 구현했습니다. 실제 공장에 도입된 시스템이 아닌 학습·포트폴리오용 개인 프로젝트입니다.

### 생산관리 포트폴리오의 중심

- **생산 영향:** 제품별 계획량·원료 기준 생산 가능량·부족량·주문과 납기 위험을 확인합니다. 공유 원료를 중복 배정하지 않습니다.
- **대응 비교:** 입고 앞당기기·추가 확보·생산일 변경을 원본과 분리해 비교합니다. 감산으로 부족이 줄었는지도 함께 표시합니다.
- **쓸 수 있는 재고:** 냉장·냉동을 구분하고, 검사대기·사용보류·준비일·사용기한을 반영합니다. 품질 적합 판정은 사람이 입력합니다.
- **검토 근거:** 담당 역할·기한·대응·결과와 계산 입력을 연결해 조치 이력을 새 버전으로 쌓습니다. 자동 발주·승인은 하지 않습니다.

[넣은 이유와 대표 시연](docs/PRODUCTION_PLANNING.md) · [입력 양식·계산 가정](docs/PRODUCTION_PLANNING.md#현재-입력-양식)

|---|---|---|
| 생산·원료·재고 관리 업무를 살펴보는 사용자 | 공공 재고·가격 + 공장 CSV | 시장 경보, 소진 예정일, 발주 기한·수량, 행동 안내 |

## 화면으로 보는 핵심 기능

### 01. “재고 부족”을 날짜와 수량으로 풀어 보기

대표 화면 `오늘의 생산 위험`은 원료 기준으로 만들 수 있는 양·부족량·영향받는 계획을 먼저 보여 주고, 그 아래에 해동·소비기한·지시서·원가 한 줄 요약과 원료별 긴급·발주 필요 안내가 이어집니다. 예를 들어 **소진일보다 가장 빠른 입고일이 늦으면**, 긴급 구매·입고 앞당기기·정규 발주·생산계획 조정을 나누어 안내합니다.

시장 재고와 소비자가는 참고 신호로 덧붙입니다. 전국 시장 재고를 우리 공장 재고로 해석하거나 소비자가를 실제 매입 단가로 쓰지 않도록 구분했습니다.

### 02. 추이와 예측을 보고, 과거 구간에서 성능을 비교하기

### 우리 공장 CSV 연결

```text
재고 + 입고 예정 + 생산계획 + 배합표
                  ↓
원료별 예상 사용량과 입출고 계산
                  ↓
소진 예정일 · 안전재고 미달일 · 발주 기한 · 필요한 수량
                  ↓
오늘의 현황에 행동 안내
```

처음에는 `오늘의 생산 위험 → 샘플로 생산 차질 확인`을 누르면 됩니다. 샘플 모드는 실제 회사 파일 없이 계산을 살펴보는 용도입니다. 입력 열과 계산 규칙은 [생산관리 입력 안내](docs/PRODUCTION_PLANNING.md)에 정리했습니다.

## 설계에서 고민한 점

- **실제·회사·합성 데이터 구분.** 출처, 단위, 주기가 다른 데이터를 한 숫자로 섞지 않고 메뉴와 안내 문구로 나눴습니다.
- **통계를 현장 언어로 표현.** “평소보다 29% 적음”, “오늘까지 4.6톤 발주”처럼 화면에서 의미와 행동을 읽을 수 있게 했습니다.
- **예측은 기준선과 비교.** 복잡한 모델을 썼다는 이유로 더 좋다고 판단하지 않습니다. 오차를 비교하고 성능이 부족하면 그대로 밝힙니다.
- **수집 실패도 데이터의 일부.** 호출 예산, 날짜별 누적 저장, 인증 오류 시 중단, 결측·급변 점검을 둬 수집 상태까지 확인합니다.
- **같은 경보는 반복 발송하지 않기.** 수집 후 새 경보만 Windows 알림과 이력에 남깁니다. 샘플 공장 데이터는 실제 공장 알림에서 제외합니다.

## 실행 방법

### 공개 샘플 체험판 배포

Streamlit Community Cloud에 이 저장소의 `main` 브랜치와 **`public_app.py`**로 배포했습니다. 공개 체험판은 기존 합성 데이터와 날짜별 샘플 공장 데이터로 계산하며, 회사 CSV 업로드·서버 파일 저장·로컬 회사 파일 열람을 차단합니다. 조치 이력과 원가 가정은 접속 세션 동안만 유지됩니다. 실제 회사 자료를 넣지 마세요.

`실제 데이터`와 `환율`은 공장 샘플과 구분된 공공데이터입니다. 공개판은 [키가 없는 공공데이터 스냅샷](data/public_live/README.md)을 기본으로 보여 주고, 아래 비공개 설정이 있으면 서버가 제한된 횟수로 최신 데이터를 받습니다. 방문자에게 API 키나 갱신 버튼을 제공하지 않습니다. Streamlit Cloud의 로컬 저장은 영구 보관되지 않을 수 있으므로, 이 화면은 실시간 시황이 아니라 표시된 날짜 기준의 참고 자료입니다.

배포 관리자만 Streamlit Community Cloud의 **앱 Settings → Secrets**에 아래 두 항목을 최상위 항목으로 입력합니다. 값은 예시이며 실제 키를 README, GitHub, 화면, `.streamlit/secrets.toml`의 추적 파일에 넣지 않습니다. 이미 배포한 앱도 Settings에서 Secrets를 추가·변경할 수 있습니다. [Streamlit 공식 안내](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management)

주의: 축산물품질평가원 API의 [공식 요청주소](https://www.data.go.kr/data/15000577/openapi.do)는 HTTP로 안내됩니다. 이 방식은 **방문자와 GitHub로부터 키를 숨기지만**, 제공기관까지 가는 구간의 암호화까지 보장하지는 않습니다. 해당 기관의 HTTPS 지원 여부를 확인하기 전에는 이 차이를 알고 사용해야 합니다.

```toml
KEY_EKAPE_DISTRIB = "발급받은_인코딩된_키"
KEY_KOREAEXIM = "발급받은_환율_API_키"
```

[공개 체험판 열기](https://meat-supply-dashboard-v7hj4kxyd29zjedcq55mz9.streamlit.app/) · 로컬에서 CSV를 올려 전체 기능을 쓰려면 아래의 기존 `app.py` 실행 방법을 이용하세요.

### 화면부터 살펴보기

```bash
pip install -r requirements.txt
streamlit run app.py
```

[http://localhost:8501](http://localhost:8501)을 엽니다. API 키가 없어도 합성 데이터 시연과 공장 샘플 계산을 살펴볼 수 있습니다. 수집된 실제 데이터가 없으면 실제 데이터 화면은 별도 수집이 필요합니다.

### 실제 공공데이터 연결 — Windows

```bat
setup.bat
copy .env.example .env
REM .env의 KEY_EKAPE_DISTRIB에 발급받은 키를 입력합니다.
.venv\Scripts\python collect.py
run.bat
```

로컬 실행의 API 키는 `.env`, 공개 배포의 API 키는 Streamlit Secrets에만 둡니다. 둘 다 Git에 포함하지 않습니다. 로컬에서 수집한 실제 데이터는 `data/live/`, 입력한 공장 CSV는 `data/company/`에 보관하며 두 폴더의 운영 데이터도 Git에서 제외합니다.

자동 수집 등록·해제, 경보 설정, 문제 해결 등 기존 상세 사용법은 [운영 안내](docs/OPERATIONS.md)에서 볼 수 있습니다.

## 데이터의 한계

실제 재고는 월 단위이며 공개가 약 2~3개월 늦습니다. 표본이 작아 예측은 보조 정보로 사용해야 합니다. 돼지 경락가의 지역 범위, 실제 소비량·유통 마진 등 확보하지 못한 지표도 별도로 밝혔습니다.

공장 계산은 입력한 생산계획·배합표·입고 일정에 의존합니다. 대체 원료는 대체표에 허용된 것만 후보로 제안하며, 원가 최적화(원료비만 계산하고 가공비·물류비는 제외)나 실제 주문 실행은 다루지 않습니다. 제품별 가능량은 원료와 라인 하루 최대 생산량(설정 시)을 고려하며, 세부 설비 시간·인력·포장재·운송·최소 배치 제약은 제외합니다. 납기 위험은 실제 지연 일수 예측이 아닙니다. 기한·품질 상태가 없는 기존 입력은 가정이 표시됩니다. 이 프로젝트의 행동 안내는 의사결정을 돕는 계산 결과입니다.

## 앞으로 넣어 보고 싶은 것

- **매입 단가 이력·추이** — 원료별 매입 단가가 시간에 따라 어떻게 움직였는지 보는 화면입니다. 입고 건별 단가와 적용일을 쌓아 추이 그래프로 그리고, 같은 기간의 경락가·환율과 나란히 놓아 "단가가 오른 게 시세 때문인지 환율 때문인지"를 나눠 보고 싶습니다. 지금은 원가 영향 화면이 현재 단가 한 시점만 다룹니다. 매입 이력이 실제로 어떤 형식(ERP 매입 내역, 월별 계약가 등)으로 쌓이는지 정하지 못해 이번에는 넣지 않았습니다.
